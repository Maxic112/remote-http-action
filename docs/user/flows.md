# Flow

Flow — именованная последовательность [действий](actions.md), которая запускается запросом `POST` к адресу flow.

## Основное

| Параметр | Описание |
|---|---|
| Название | Отображается в окне, в истории и в списке доступных flow. |
| Путь | Часть адреса после префикса. Путь `sleep` даёт адрес `POST /flow/sleep/`. Допустимы символы `a-z`, `0-9`, `-`, `_` и `/` (например `pc/power-off`). Регистр приводится к нижнему, косые черты по краям отбрасываются. |
| Описание | Произвольный текст. |
| Включён | Выключенный flow не вызывается по HTTP (`404`) и не попадает в список доступных. |

## Выполнение

| Параметр | По умолчанию | Описание |
|---|---|---|
| Режим ответа | Дождаться результата | **sync** — сервер ждёт окончания flow и возвращает результат. **async** — сервер сразу отвечает `202` с идентификатором запуска; статус запрашивается отдельно. |
| Таймаут flow | 60 сек | Максимальное время выполнения всех шагов (задержка старта не учитывается), до 7 суток. По истечении выполнение прерывается, запуск получает статус `timeout`. |
| Повторный вызов во время выполнения | Отклонять | **Отклонять** — ответ `409`, пока предыдущий запуск не завершён. **Ставить в очередь** — запуски выполняются строго по одному. **Разрешать параллельно** — без ограничений. |
| Пауза между запусками | 0 | Минимальный интервал между стартами. Вызов раньше срока получает `429`. |
| Задержка старта | 0 | Перед выполнением на компьютере показывается окно с обратным отсчётом и кнопкой отмены. Подходит для выключения и перезагрузки. |
| Можно отменить | Да | Разрешает отмену запуска через HTTP и CLI. Из окна приложения отменить можно любой запуск. |

Совет: для flow с выключением или перезагрузкой используйте режим **async** или небольшую задержку старта.
Тогда клиент гарантированно получит ответ до отключения компьютера.

## Данные для клиента

Поля вкладки **Клиент** не влияют на выполнение. Они возвращаются в списке доступных flow (`/get-allowed/`) для клиентских приложений:

- иконка, цвет, категория, теги;
- «Клиент должен запрашивать подтверждение» — подсказка клиенту спросить пользователя перед вызовом.

## Шаги

Шаги выполняются строго по порядку. Порядок меняется кнопками «Выше» и «Ниже».
У каждого шага задаются:

- поведение **при ошибке**: остановить flow или продолжить;
- собственный **таймаут**;
- признак **«Требует прав администратора»**. Такие шаги помечены иконкой щита, а flow с ними — щитом в списке.

Если хотя бы один шаг завершился ошибкой, запуск получает статус `failed`. Это верно и тогда, когда остальные шаги выполнились из-за «продолжить».
