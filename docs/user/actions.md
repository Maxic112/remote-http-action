# Действия

Действие — один шаг [flow](flows.md). У всех действий есть общие параметры, у каждого типа — свои.

## Общие параметры

| Параметр | Описание |
|---|---|
| При ошибке | `stop` — остановить flow (по умолчанию), `continue` — перейти к следующему шагу. |
| Таймаут шага | Максимальное время шага в секундах. Пусто — ограничивает только таймаут flow. |
| Требует прав администратора | Шаг выполняется, только если приложение запущено с правами администратора. Иначе шаг завершается ошибкой `ADMIN_REQUIRED` (см. [Права администратора](administrator-rights.md)). |
| Возвращать вывод клиенту | Только для команд: stdout и stderr включаются в HTTP-ответ. По умолчанию клиент получает только статус и код выхода. |

## Выключить компьютер — `shutdown`

| Параметр | Описание |
|---|---|
| `force` | Не ждать закрытия программ (несохранённые данные будут потеряны). |

## Перезагрузить компьютер — `reboot`

| Параметр | Описание |
|---|---|
| `force` | Как у `shutdown`. |

## Спящий режим — `sleep`

| Параметр | Описание |
|---|---|
| `hibernate` | Гибернация вместо сна. |

Переход в сон происходит примерно через 1,5 секунды после выполнения шага. За это время клиент успевает получить ответ.

## Задержка — `delay`

| Параметр | Описание |
|---|---|
| `seconds` | Пауза перед следующим шагом, от 0 до 86400 (допускаются дробные значения). |

## Выполнить команду — `cli_command`

| Параметр | Описание |
|---|---|
| `shell` | Оболочка: `cmd`, `powershell` (Windows PowerShell), `pwsh` (PowerShell 7), `wsl`. Список доступных оболочек определяется автоматически. |
| `command` | Текст команды. |
| `working_dir` | Рабочая папка (необязательно). |

Команда выполняется без окна консоли. Кодировка вывода определяется автоматически: UTF-8 или OEM-кодировка консоли Windows.
Поэтому кириллица корректно отображается и у встроенных команд `cmd`, и у PowerShell.
Код выхода, отличный от 0, считается ошибкой шага.
Вывод сохраняется в истории запусков (до 16 КБ на поток).

## Выполнить скрипт — `run_script`

| Параметр | Описание |
|---|---|
| `shell` | Чем выполнять: `cmd` (файлы `.bat`, `.cmd`), `powershell` / `pwsh` (`.ps1`, запускается с `-ExecutionPolicy Bypass`), `wsl` (скрипт `sh`). |
| `script_path` | Путь к файлу скрипта. В окне его можно выбрать кнопкой «Обзор…». Для `wsl` путь Windows (`C:\dir\job.sh`) автоматически преобразуется в `/mnt/c/dir/job.sh`; путь внутри WSL указывается как есть. |
| `args` | Список аргументов. В окне — по одному в строке. Аргументы передаются как есть, без интерпретации оболочкой. |
| `working_dir` | Рабочая папка; по умолчанию — папка скрипта. |

Если файл не найден, шаг завершается ошибкой до запуска.
Вывод, код выхода и признак «Возвращать вывод клиенту» работают так же, как у `cli_command`.

## Запустить приложение — `launch_app`

| Параметр | Описание |
|---|---|
| `path` | Путь к программе (`.exe`, `.bat`, `.cmd`). В окне — кнопка «Обзор…». |
| `args` | Список аргументов, по одному в строке. |
| `working_dir` | Рабочая папка; по умолчанию — папка программы. |
| `wait` | Режим ожидания, см. ниже. По умолчанию `none`. |
| `wait_process_name` | Для `wait: name`: имя процесса, например `steam.exe`. По умолчанию — имя файла из `path`. |
| `wait_start_timeout_sec` | Для `wait: name`: сколько секунд ждать появления процесса, по умолчанию 60. Если процесс не появился, шаг завершается ошибкой. |

Программа запускается со своим окном на рабочем столе пользователя, под которым работает Remote HTTP Action, и с теми же правами.
Если приложение запущено от имени администратора, запущенная программа тоже получит права администратора.

### Режимы ожидания

| `wait` | Шаг завершается | Подходит для |
|---|---|---|
| `none` | Сразу после запуска программы. | Запуск «в фоне». |
| `process` | Когда завершится запущенный процесс. Ненулевой код выхода — ошибка шага. | Обычные программы и утилиты. |
| `tree` | Когда завершатся запущенный процесс и все процессы, которые он породил (отслеживается через job object Windows). | Лаунчеры, которые запускают основную программу и сразу выходят. |
| `name` | Когда не останется ни одного процесса с именем `wait_process_name`. Шаг сначала ждёт появления процесса, затем — его исчезновения; процесс считается закрытым после трёх проверок подряд с интервалом в секунду, поэтому перезапуск программы (например, после обновления) не прерывает ожидание. | Программы, которые уже могут быть запущены, работают в единственном экземпляре или перезапускают себя: Steam, Блокнот Windows 11. |

Отмена запуска или таймаут flow прекращают **ожидание**, но не закрывают программу.

Многие программы — лаунчеры: запущенный файл передаёт работу другому процессу и сразу завершается.
Так ведут себя Блокнот Windows 11 (запускает версию из Microsoft Store) и Steam (если он уже открыт, новый `steam.exe` передаёт команду работающему экземпляру).
Для них режим `process` завершается сразу, используйте `name`.

Пример: запустить Steam и после его закрытия выполнить следующие шаги.

```json
{
  "name": "Игровая сессия",
  "path": "gaming",
  "response_mode": "async",
  "timeout_sec": 43200,
  "actions": [
    {
      "type": "launch_app",
      "params": {
        "path": "C:\\Program Files (x86)\\Steam\\steam.exe",
        "wait": "name",
        "wait_process_name": "steam.exe"
      }
    },
    { "type": "sleep", "params": {} }
  ]
}
```

Для flow с ожиданием долгой программы выберите режим ответа **async** (иначе HTTP-клиент будет ждать ответа всё это время) и задайте достаточный таймаут flow.

Пример flow, заданного в JSON (см. [CLI](cli.md#flow)):

```json
{
  "name": "Перезапуск службы печати",
  "path": "restart-spooler",
  "actions": [
    {
      "type": "cli_command",
      "params": { "shell": "powershell", "command": "Restart-Service Spooler" },
      "run_as_admin": true,
      "capture_output": true
    }
  ]
}
```
