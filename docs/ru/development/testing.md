# Тестирование

## Команды

| Команда | Что проверяет |
|---|---|
| `pnpm test:all` | Проверку типов TypeScript, тесты фронтенда и все тесты Rust |
| `pnpm test` | Тесты фронтенда (Vitest) |
| `pnpm test:rust` | Тесты Rust (`cargo test`) |
| `pnpm lint` | ESLint, Prettier, rustfmt, clippy (предупреждения считаются ошибками) |

## Rust

| Где | Что |
|---|---|
| `#[cfg(test)] mod tests` рядом с кодом | Unit-тесты: настройки, генерация ключей, разбор параметров действий, сетевые фильтры, защита от перебора, репозитории SQLite (in-memory), runner, CLI-разбор |
| `src/http/tests.rs` | Интеграционные тесты HTTP API на реальном сокете (`127.0.0.1:0`) с клиентом reqwest |
| `src/ipc.rs` | Обмен через настоящий транспорт: named pipe на Windows, Unix socket на других ОС |
| `src/platform/autostart.rs` | Генерация XML задания. Тест `autostart_round_trip` (помечен `#[ignore]`) создаёт и удаляет настоящее задание; нужен повышенный терминал: `cargo test -- --ignored autostart_round_trip` |
| `src/tls.rs`, `src/http/tests.rs` | Генерация сертификата, HTTPS-сервер на реальном сокете |
| `src/logs.rs` | Запись, ротация, чтение через архивные файлы |
| `src/platform/system.rs` (только Windows) | Реальный запуск `cmd` и PowerShell, кодировка вывода, рабочая папка, принудительное завершение процесса, определение оболочек |

Действия ОС в тестах ядра выполняются через `MockPlatform` (`src/platform/mock.rs`):

- записывает вызовы питания и процессы;
- возвращает заданные ответы с задержкой;
- имитирует права администратора.

`SystemPlatform` в тестах всегда создаётся с `dry_run_power: true`.

Хелперы для тестов: `core::tests::core_with(platform)` создаёт ядро с базой в памяти, `core::tests::sample_flow(path)` создаёт минимальный flow.

## Frontend

Тесты лежат рядом с кодом (`*.test.ts`, `*.test.tsx`), окружение — jsdom.

- `src/test/utils.tsx` подменяет `@tauri-apps/api/core` и `@tauri-apps/api/event`.
- `mockApi({ op: handler })` задаёт ответы ядра по полю `op` и возвращает список полученных запросов. По нему проверяется, что UI отправил правильный `Request`.
- `renderWithProviders` оборачивает компонент в QueryClient и TooltipProvider.
- Тексты ищутся по английской локали: она включается в `src/test/setup.ts`.
- Для чекбоксов Base UI используйте `getByRole("checkbox", { name })`: `getByLabelText` находит два элемента.

## Сквозной smoke-тест

`scripts/smoke.ps1` запускает настоящий исполняемый файл в режиме `--headless`. Для запуска используются:

- временная папка данных;
- отдельное имя pipe;
- `RHA_DRY_RUN_POWER=1`.

Скрипт настраивает flow, группу и ключ через CLI и затем проверяет:

- HTTP API и историю запусков;
- коды выхода CLI;
- выполнение скрипта PowerShell с аргументами;
- содержимое журналов (в том числе отсутствие секрета);
- переключение на HTTPS и обратно;
- статус автозапуска;
- завершение процесса.

```bash
cargo build --manifest-path src-tauri/Cargo.toml --bins
pwsh -File scripts/smoke.ps1
```

CLI-команды скрипт выполняет через `remote-http-action-cli.exe`. Одну команду он отправляет через основной exe, чтобы проверить и этот путь.

Скрипт требует отладочную сборку: в ней CLI включён по умолчанию. Окно для проверки не нужно, поэтому скрипт работает и в неинтерактивной сессии.

## Ручная проверка

Сценарии, которые требуют окна в сессии пользователя, проверяются вручную на собранном приложении:

- трей и поведение при закрытии окна;
- перезапуск с повышением прав и UAC;
- окно обратного отсчёта;
- реальные действия питания.
