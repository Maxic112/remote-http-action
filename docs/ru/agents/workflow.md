# Рабочий процесс агента

## Перед началом

1. Прочитайте `AGENTS.md` и разделы `docs/en/` (или `docs/ru/`), относящиеся к задаче.
2. Найдите точку входа:
   - новая операция пользователя → `src-tauri/src/core.rs` (`Request`);
   - поведение HTTP → `src-tauri/src/http/mod.rs`;
   - выполнение flow → `runner.rs`, `actions.rs`;
   - интерфейс → `src/features/<раздел>/`.
3. Посмотрите существующие тесты рядом с изменяемым кодом: они показывают ожидаемое поведение и готовые хелперы.

## Во время работы

- Сначала тест на новое поведение, затем реализация. Для HTTP — сценарий в `http/tests.rs`.
- Не обращайтесь к ОС напрямую из ядра: только через трейт `Platform`, чтобы код тестировался с `MockPlatform`.
- Типы Rust и TypeScript меняйте вместе (`model.rs`/`settings.rs`/`core.rs` ↔ `src/lib/types.ts`).
- Новые строки UI добавляйте сразу в обе локали.
- Документацию меняйте сразу в `docs/en/` и `docs/ru/`.
- Комментарии в коде — только на английском и только неочевидное.
- Если меняется формат, хранимый в базе:
  - добавьте новую миграцию в конец `MIGRATIONS` (существующие не редактируйте);
  - либо используйте `#[serde(default)]` для полей JSON-документов.

## Перед завершением

1. `pnpm lint` и `pnpm test:all` — без ошибок и предупреждений.
2. Документация обновлена ([чек-лист](checklist.md)).
3. Если изменились правила работы с репозиторием или карта кода — обновлён `AGENTS.md`.

## Чего не делать

- Не запускать в тестах настоящие выключение, перезагрузку и сон.
- Не логировать и не возвращать секреты ключей.
- Не добавлять в HTTP API операции изменения конфигурации.
- Не давать CLI доступ к переключателю `cli.enabled`.
- Не упоминать в документации процесс разработки, конкретные машины и сети.
