# Обзор компонентов

## Один исполняемый файл, два режима

`remote-http-action.exe` без аргументов запускает приложение (окно, трей, HTTP-сервер, IPC-сервер).
С аргументами работает как CLI-клиент: разбирает команду, передаёт её запущенному экземпляру и печатает результат.

Аргументы режима приложения:

| Аргумент | Назначение |
|---|---|
| `--minimized` | Запуск без показа окна (только трей). |
| `--headless` | Запуск без окна и трея: только HTTP-сервер и CLI-канал. Остановка — `app quit` или Ctrl+C. Подходит для автоматизации и сред без рабочего стола. |
| `--wait-pid <pid>` | Дождаться завершения указанного процесса перед стартом (используется при перезапуске с повышением прав). |

## Слои

```
┌──────────── UI (React) ────────────┐   ┌──── CLI-клиент ────┐   ┌──── HTTP-клиенты ────┐
│ invoke("api", Request)             │   │ clap → Request     │   │ POST /flow/...        │
└───────────────┬────────────────────┘   └─────────┬──────────┘   └──────────┬────────────┘
                │ Tauri command                     │ named pipe              │ axum
                ▼                                   ▼                         ▼
        ┌──────────────────────── Core (core.rs) ─────────────────────────────────────┐
        │ handle(Caller, Request)        settings        HttpServer    BruteForceGuard │
        └───────┬───────────────────────────┬──────────────────────┬──────────────────┘
                ▼                           ▼                      ▼
             Db (SQLite)              Runner (runner.rs)      EventSink → UI
                                            │
                                            ▼
                                  actions.rs → Platform (ОС)
```

- **Core** — единая точка операций. UI и CLI отправляют одинаковые `Request`, поэтому их возможности совпадают по построению.
  Отличие одно: CLI не может менять настройку `cli.*`.
- **HttpServer** — axum с одним обработчиком. Префиксы путей читаются из настроек на каждый запрос, поэтому их смена не требует перезапуска.
  Сервер перезапускается только при смене адреса или порта.
- **Runner** — запускает flow в фоновых задачах tokio. Отвечает за очередь, паузу между запусками, задержку старта, таймауты и отмену (`CancellationToken`).
  Также сохраняет историю запусков.
- **actions.rs** — проверка параметров и выполнение каждого типа действия.
- **Platform** — трейт для действий ОС.
  - `SystemPlatform` выполняет их на Windows.
  - `MockPlatform` записывает вызовы в тестах.
  - Переменная окружения `RHA_DRY_RUN_POWER=1` заменяет действия питания записью в журнал.
- **Logger** (`logs.rs`) — журналы `http`, `cli`, `flow` в JSON Lines с ротацией по размеру. Пишут HTTP-обработчик (имя ключа передаётся через task-local), IPC-диспетчер и runner.
- **TLS** (`tls.rs`) — самоподписанный сертификат (rcgen) или PEM пользователя, rustls с провайдером `ring`. Сервер построен на `axum-server`: один путь кода для HTTP и HTTPS, остановка через `Handle`.
- **Обновление** (`update.rs`) — проверка релизов (формат GitHub API), скачивание с проверкой SHA-256, установка через PowerShell-помощник. Помощник ждёт выхода приложения, затем запускает `msiexec` или заменяет exe портативной версии, перезапускает приложение и удаляет временные файлы. Результат проверки хранится в таблице `settings` под ключом `update_state`.
- **Автозапуск** (`platform/autostart.rs`) — XML задания планировщика и вызовы `schtasks.exe`.
- **EventSink** — события ядра (изменение данных, ход запуска, задержка старта, состояние сервера). GUI пересылает их в окно событием `app-event`.

## Поток вызова flow

1. axum принимает запрос и определяет адрес клиента с учётом доверенных прокси.
2. Проверяются список адресов, заголовок `Host`, блокировка, API-ключ и доступ через группы.
3. `Runner::start` проверяет, что flow включён, валидирует действия, применяет политику повторного вызова и паузу. Затем создаёт запись запуска и фоновую задачу.
4. Задача выдерживает задержку старта (окно обратного отсчёта получает событие `run_delayed`) и выполняет шаги.
5. В режиме sync обработчик ждёт завершения, в режиме async сразу отвечает `202`.

## Окно и трей

- Окно создаётся скрытым и показывается после инициализации; с флагом `--minimized` остаётся скрытым.
- Закрытие окна скрывает его или завершает приложение, в зависимости от настройки `app.close_to_tray`.
- Меню трея: «Открыть», переключатель HTTP-сервера, «Выход».
- Повторный запуск exe без аргументов показывает окно уже работающего экземпляра (плагин single-instance).

## Перезапуск с повышением прав

`Request::AppRestartElevated` вызывает `ShellExecuteExW` с глаголом `runas` и параметром `--wait-pid <текущий pid>`.
Затем текущий процесс завершается. Новый процесс ждёт его выхода и только после этого занимает блокировку single-instance, pipe и порт.

## Хранение данных

| Режим | Папка данных |
|---|---|
| Установленная версия | `%APPDATA%\remote-http-action\` (`-dev` в отладочных сборках) |
| Портативная версия | `data\` рядом с exe при наличии `portable.flag` |
| Переопределение | переменная окружения `RHA_DATA_DIR` |

В папке находятся:

- `data.db` — SQLite в режиме WAL;
- `logs\` — журналы;
- `tls\` — самоподписанный сертификат, если он создан.
