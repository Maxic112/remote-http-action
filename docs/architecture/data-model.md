# Модель данных

Данные хранятся в SQLite (`data.db`). Схема создаётся и обновляется миграциями из `src-tauri/src/db.rs`.
Номер применённой миграции хранится в `PRAGMA user_version`.
Если база создана более новой версией приложения, запуск прерывается с ошибкой.

## Таблицы

| Таблица | Содержимое |
|---|---|
| `api_keys` | `name`, `key_prefix` (первые 12 символов ключа), `key_hash` (SHA-256, уникальный), `enabled`, `created_at`, `last_used_at` |
| `access_groups` | `name` (уникальное), `description`, `created_at` |
| `api_key_groups` | связь ключ ↔ группа, каскадное удаление |
| `flows` | `path` (уникальный), `data` — JSON с параметрами flow и списком действий, `created_at`, `updated_at` |
| `group_flows` | связь группа ↔ flow, каскадное удаление |
| `settings` | одна запись `app` с JSON всех настроек |
| `runs` | история запусков: flow (`flow_id` обнуляется при удалении flow, имя и путь сохраняются), источник, ключ, адрес клиента, статус, время, ошибка, JSON шагов |

## Flow в JSON

Параметры flow (`FlowInput`) хранятся одним JSON-документом. Действия — массив внутри него.
Это упрощает добавление полей: недостающие поля получают значения по умолчанию при чтении.
Тот же формат принимает CLI (`flows create --file`).

## Настройки

Настройки — один JSON-документ (`Settings`). Отсутствующие поля заполняются значениями по умолчанию.
Значение `cli.enabled` по умолчанию зависит от сборки: `true` в отладочной, `false` в релизной.

## История запусков

После каждого запуска удаляются завершённые записи сверх лимита `app.run_history_limit`.
При старте приложения незавершённые запуски предыдущего процесса помечаются как `failed`.
