# CLI и IPC

## Схема

```
remote-http-action-cli.exe keys list
        │ clap: разбор аргументов, --help/--version локально
        ▼
   Request (JSON)  ──►  \\.\pipe\remote-http-action  ──►  запущенный экземпляр
                                                          ├─ cli.enabled? иначе CLI_DISABLED
                                                          └─ Core::handle(Caller::Cli, request)
   печать таблицы / JSON  ◄──  IpcResponse { data | error }
```

CLI не обращается к базе данных: все операции выполняет работающий экземпляр.
Так данные остаются согласованными, а окно сразу видит изменения (событие `data_changed`).

## Протокол

Одно соединение — один запрос. Клиент пишет строку JSON и завершает её переводом строки:

```json
{"request": {"op": "key_create", "name": "Телефон", "group_ids": [1]}}
```

Сервер отвечает одной строкой:

```json
{"data": {...}, "error": null}
```

или

```json
{"data": null, "error": {"code": "NOT_FOUND", "message": "..."}}
```

Формат `request` совпадает с тем, что UI передаёт в команду Tauri `api` (перечисление `Request`, поле-тег `op`).

## Транспорт

| ОС | Транспорт | Имя |
|---|---|---|
| Windows | Named pipe | `\\.\pipe\remote-http-action`, в отладочных сборках `\\.\pipe\remote-http-action-dev` |
| Прочие (для разработки) | Unix socket | `<папка данных>/ipc.sock` |

Имя можно переопределить переменной окружения `RHA_IPC_ENDPOINT`.

### Права доступа к pipe

Дескриптор безопасности:

- полный доступ: `SYSTEM`, `Administrators` и SID пользователя, запустившего приложение;
- метка целостности Medium: терминал без повышения прав может подключиться к экземпляру, запущенному от имени администратора;
- первый экземпляр pipe создаётся с флагом `FILE_FLAG_FIRST_PIPE_INSTANCE`, чтобы другой процесс не мог перехватить имя;
- удалённые подключения к pipe отклоняются.

## Вывод в консоль

CLI-клиент есть в двух исполняемых файлах, код у них общий (`cli::run`):

| Файл | Подсистема | Поведение в терминале |
|---|---|---|
| `remote-http-action-cli.exe` (`src/bin/remote-http-action-cli.rs`) | консольная | Терминал ждёт завершения, вывод и код выхода работают как у обычной консольной утилиты. |
| `remote-http-action.exe` с аргументами | GUI (в релизе) | Подключается к консоли родителя (`AttachConsole`), если вывод не перенаправлен. `cmd` и PowerShell не ждут GUI-процессы, поэтому вывод может появиться после приглашения. С перенаправлением (`> file`, конвейер) работает корректно. |

Подсистема exe фиксируется при сборке, и именно по ней оболочка решает, ждать ли процесс. Поэтому для интерактивной работы нужен отдельный консольный файл.
