# Авторизация

## API-ключ

Каждый запрос, кроме публичного статуса, должен содержать API-ключ в одном из заголовков:

```
Authorization: Bearer rha_...
X-API-Key: rha_...
```

Ключ в параметрах URL не принимается.

| Ситуация | Ответ |
|---|---|
| Ключ не передан | `401`, `UNAUTHORIZED`, «API key required» |
| Ключ неверный или выключен | `401`, `UNAUTHORIZED`, «invalid API key» |
| Ключ верный, но flow не входит в его группы | `403` (или `404`, если включено скрытие недоступных flow) |

## Порядок проверок

Каждый запрос последовательно проходит проверки:

1. **Адрес клиента.** Для запросов от доверенных reverse proxy адрес берётся из `X-Forwarded-For`.
   Заголовок разбирается справа налево, доверенные прокси пропускаются. Для остальных запросов используется адрес TCP-подключения.
2. **Список разрешённых адресов.** Если список задан и адрес в него не входит — `403`.
3. **Заголовок Host.** Если список разрешённых значений задан и значение не подходит — `403`.
4. **Блокировка.** Если адрес заблокирован за перебор ключей — `429` с заголовком `Retry-After`.
5. **API-ключ и права доступа.**

## Защита от перебора

Каждый неверный ключ засчитывается адресу клиента как неудачная попытка.
Если за период набралось заданное число попыток, адрес блокируется. Блокируются все запросы с этого адреса, включая запросы с верным ключом.
Отсутствие ключа попыткой не считается.

Параметры и снятие блокировок — в [Настройках](../user/settings.md#сетевой-доступ).

## Транспорт

Сервер работает по HTTP или HTTPS (см. [HTTPS](../user/https.md)). Для доступа из недоверенных сетей включите HTTPS или разместите сервер за reverse proxy с HTTPS.
В последнем случае добавьте адрес прокси в список доверенных.
